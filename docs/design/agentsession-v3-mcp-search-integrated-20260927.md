此前 3.0 的[首份冻结测量](agentsession-v3-mcp-search-20260927.md)在正文 35 页查询上为 8.66 秒，且总响应约 3.72 MB。本轮集成了 FTS 外循环、Codex header 缓存和 MCP 文本摘要去重，正文 35 页为 1.65 秒、响应约 1.78 MB；这两份测量的 3.0 binary 不同，因此只说明当前候选的真实结果，不能把差值当作单个改动的因果收益。当前 3.0 在几项短中文、字面百分号和无命中查询上仍慢于 2.0；也不能据此声称所有搜索路径全面更快。

被测 2.0 固定提交为 `50a32e7c5b3fdaa1d335771da80d6c919d4ab536`，运行树摘要 `d01277bcd9b69de6cb1faf6d536be28f8aae8f658950a544039de3da969d92b4`。3.0 binary SHA-256 为 `c8e6cc77079aa1e38b6332c9a5ac53ea110dfef68697c3b655a21ed7ee64b090`，配对产物摘要 `dcbc48f7985af9391a07201f4b48e3e5dc0a133f401b27350a8bd63532ebf50c`。Codex 来源含 840 个文件、3,400,267,634 字节；前后用 stat manifest 校验，其他四 provider 校验内容 manifest。九项结果的独立来源 golden 为 `ad65fc5aa00382300c622501cc9946313f4c08599bd09dffa0ad4f0b2088cae1`。公开摘要记录五次的每项原始毫秒数、状态、来源签名和限制；本报告未公开原始查询或会话正文。

OS 文件缓存没有受控；来源预扫描可能暖化数据和元数据。测量期间执行过少量安装器/包检查，因而它不是隔离机器上的纯负载实验。RSS 与 CPU 只覆盖 MCP 主进程，两次进程是先后启动，不代表并发。本测量只验证 stdio MCP 搜索的匹配语义、就绪、分页与资源；来源变化、Reader/Web、并行负载及后续功能改动后的最终产物仍需分别验收。
