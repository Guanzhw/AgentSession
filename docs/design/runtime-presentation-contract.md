## 1. 用户来这里做什么

AgentSession 是 **agent 工作历史阅读器**：完整记录是内容，运行关系是组织方式，连续阅读是默认体验。
读者应能在一个阅读上下文里回答：

1. 我提出了什么，agent 最终回答或交付了什么？
2. 期间把哪些工作交给了谁；哪些并行进行、后来继续、被中断或返回？
3. 某个结论来自哪次执行或返回；能否读到完整原文？
4. compact、memory 等发生后，记录中保存了什么结果和上下文？
5. 哪些是这次执行新产生的工作，哪些只是继承的背景？

“默认简洁”和“记录完整”同时成立：折叠改变可见密度，不改变记录归属、搜索范围和完整内容的可达性。
阅读顺序与运行关系可以不同；主线程继续工作时，后台分支保持自己的身份与生命周期。

## 2. 页面职责

| 页面或区域 | 读者任务 | 默认内容与组织 | 次级内容 |
| --- | --- | --- | --- |
| 会话库 Library | 找到要回看的工作 | 以可读标题为主，项目与最近记录时间为辅；日期分组；搜索和少量常用过滤 | Provider、协作规模、用量和诊断按需查看；已有紧凑列表作为密度选项 |
| 历史阅读页 Reader | 连续阅读并理解运行过程 | 用户请求、agent 回复、局部协作节点和上下文变化；一条主阅读路径 | 执行详情、协作概览、原始事件、用量详情 |
| 用量 Statistics | 比较消耗及来源 | 明确范围、时间、provider 和统计口径的图表与可核对明细 | 各请求、会话、后台任务的构成 |
| 设置 Settings | 管理 viewer 的读取与使用方式 | 数据目录、语言、主题、恢复命令等现有设置按用途分组 | 运行诊断与需重启的说明 |

Work / Events 保留为阅读页中的次级检查入口，名称应说明用途（如“工作关系”“原始事件”）。
读者不需要先在 Work 和 Conversation 之间选择，才能理解一次工作。
统计与设置有独立任务，保留独立页面；它们不承担解释单次运行的责任。

### 会话库的识别规则

- 标题依次使用 viewer 自定义标题、provider 可读标题、可用的首条用户请求摘录。
  摘录是原文截取，不自动生成结论。只有这些都不可用时，才显示“未命名会话”和短 ID。
- 页面标题最多占两行；完整标题和完整请求各自有可访问的查看入口。
- 主会话与有记录关系的后台会话合并为可展开的会话家族；独立打开后台会话仍保留返回来源入口。
  无法确认归属的会话保留独立可访问项。
- 默认每项只保留识别工作所需的信息；tokens、模型、时长等不以一串同权重徽章挤占标题。
- “最后记录为运行中”与真实进程在线分开表达；仅凭旧日志不能显示实时运行指示。

## 3. 内容与呈现矩阵

“默认”指普通阅读状态；“展开”指用户主动查看详情。以下是目标要求，不是现有能力清单。

| 内容 | 默认呈现 | 展开后 / 完整性 | 放置与关系 |
| --- | --- | --- | --- |
| 用户请求、后续补充 | 可读正文，清楚的请求边界 | 长文续读、原文与附件；保留结构化问答的原始来源 | 记录发生的位置；后续补充可发生在前次执行尚未结束时 |
| Agent 面向用户的回复 | 正文为主体，保留段落、表格、代码和链接 | 完整正文、准确来源、可用附件 | 所属消息位置，不按“最后一段文本”猜测 final |
| 已明确标记的中间说明、工具循环 | 合并到“执行过程”，显示有依据的数量和异常提示 | 原顺序的 commentary、工具输入输出、reasoning | 附属于产生它们的消息；不能跨请求、结果返回或上下文变化吞并节点 |
| 未区分阶段的 agent 文本 | 保留可读正文 | 原始元数据可查 | 由 provider 证据决定阶段，不能根据措辞把正文藏起来 |
| 工具调用和执行结果 | 执行过程中的工具名、简短动作、已记录状态 | 完整参数、输出、错误、日志续读；长代码局部滚动 | 同一调用的输入与结果关联，归属原 assistant 消息 |
| Reasoning | 随所属消息或工具折叠 | 读取 provider 实际提供的文本 | 不移到后一个 assistant，不恢复未记录的推理 |
| Dispatch / 分派 | 小型协作插入：可读任务名、分派动作；有记录时显示目的摘录 | 分派原文；打开子会话；精确时间和来源 | 分派发生点；开启同一任务的后续追踪 |
| Message / Follow-up | 同一任务上的沟通标记；连续密集沟通可局部折叠 | 每条消息及其准确目标和来源分别可达 | 跨多轮延续原任务，不每次新建任务卡 |
| 子任务完成与父会话接收 | 区分“子任务产生结果”和“主会话收到结果”；有原文时显示结果摘录 | 相应完整结果、子会话历史和父侧收到的原始记录 | 完成点和接收点分别保留；不得把二者合成虚构的同一时刻 |
| Interrupt / 失败 / 缺少返回 | 在相关协作插入与执行过程入口给出明确文字 | 原始错误、最后记录、重试或后续恢复证据 | 已结束日志仍保留最后已知状态，不制造持续运行的动画 |
| 子会话、后台任务、swarm/team 成员 | 有来源的目的、角色或任务名；继承背景默认收起 | 就地展开完整自身历史；可独立打开 | 身份由 canonical 引用决定，不以名称相同合并不同任务 |
| Compact | 所在位置的一行“上下文已压缩”，主动作是“查看压缩后的上下文” | 结果摘要、实际保留条目与完整续读；事件技术证据次级 | 放在记录支持的边界，不能统一搬到会话末尾 |
| Memory / dream / experience 等辅助工作 | 按记录中的实际目的显示；已知产出优先 | 产出正文、关联任务、自身新增历史与来源 | 使用相同的后台工作呈现；名称本身不证明它修改了主会话上下文 |
| 继承背景 | “继承的背景”独立折叠入口，能说明来源时显示来源 | 完整可用背景、分页和长字段续读 | 不进入子会话自身历史的 ToC、默认搜索或新增用量 |
| 文件、产物和变更 | 已记录产物紧邻相关结果；短文件名可识别 | 完整路径、可访问链接、记录中的 diff 或附件 | 不把工具提到的每个路径推断为已交付产物；不可用时明确说明 |
| Tokens / 模型 / 上下文大小 | 收入次级“用量与模型”入口；关键状态不依赖打开它 | 本次 / 含子任务的范围、输入、输出、缓存、请求数、来源与覆盖情况 | 模型变化与请求归属保留；上下文大小不是累计消耗 |
| 缺失、部分读取、加密、错误 | 在受影响处简短说明，保留已有可读内容 | 原因、可用范围、重试或其他确实存在的查看路径 | “尚未加载”“没有记录”“不可读取”是不同状态 |

### 默认折叠的边界

主阅读流保留请求、可读回复、重要协作节点和上下文变化。过程区可以包含很多调用，
但不能让读者为了看结果必须先展开它。仅有工具活动的 assistant 也保留过程入口。
中间错误若影响理解，应在折叠入口可见；详情仍留在发生位置。

结构化问答应优先显示问题与回答；解析属于 provider 边界。未支持的结构保留原文，
不把 XML 包装、内部 request ID 或 JSON 键名当作最终设计语言。

## 4. 异步关系如何可视化

主阅读流承载内容，局部连接承载关系。连接不是装饰；每条线必须有可解释的对象与端点。

- 在 dispatch、follow-up、返回的原位置插入紧凑节点。节点可选择同一任务，支持键盘操作。
- 默认保持局部关系可见；选中任务时强调该任务的相关节点和局部连线，其他关系降低权重。
  跨屏连接通过“查看分派”“查看这次返回”等文字入口保持可达，不要求读者追随整屏长线。
- 同一任务多次继续和返回使用同一身份；每一次交互仍有独立来源锚点。
- 提供默认收起的“任务与协作”右侧栏（2026-09-17 用户选定样稿 3）。正文节点可打开并选中任务，
  侧栏通过关系概览和该任务的往来序列解释分派、继续与各次返回，点击记录定位正文或准确来源。
  完整子历史仍在正文阅读。仅有足够时间证据时补充时间范围，窄屏改为可关闭的全宽检查层。
  无协作记录时不显示空侧栏。
- 正文边上的线表示记录顺序及关联，**线长不表示执行时长**。
  时间概览只有在记录支持时才表示时间范围；观察到的活动跨度不命名为 CPU 时间或连续运行时长。
- 无时间戳保留记录顺序；只有时间接近没有关系证据时不连线。
  只有子会话完成记录而没有父侧接收记录时，不能补出“已交付”的父侧节点。
- 紧邻且同类的高密度交互可以折叠为一段，必须保留数量、范围和展开路径；不能跨越用户输入、
  结果返回、任务中断或上下文变化，把重要转折抹平。

这里“可视化”的验收对象是读者能认出分派、并行、继续与返回的关系。
表格适合精确数值比较，列表适合目录和同类记录检索；复杂运行关系优先使用局部连接或时间概览。

## 5. 阅读与导航行为

| 用户操作 | 应发生什么 | 保留什么 |
| --- | --- | --- |
| 打开子会话 | 在相关协作节点附近展开完整子历史；有独立打开入口 | 父历史、父阅读位置及折叠状态 |
| 从另一节点再次打开同一子会话 | 定位已经打开的同一正文，并定位有证据的目标；不复制第二份 | 同一 canonical child 的搜索、续读及阅读状态 |
| 关闭子会话 | 回到启动该阅读操作的位置，恢复触发控件的键盘焦点 | 父滚动位置与父搜索；关闭不会改变 provider 数据 |
| 打开多级子任务 | 保留祖先导航；窄屏用全宽子阅读层和面包屑，避免无限缩进 | 每一级返回位置；独立链接可复现当前子会话 |
| 点击“查看来源” | 定位被点击的那条原始记录 | 来源 owner；不把“看父侧消息”和“打开子历史”混成一个操作 |
| 搜索 | 明确选择主会话或一个已打开的子会话；检索该范围完整的可用自身历史 | 每个范围各自的词、结果和当前位置；切换或关闭范围后无残留高亮 |
| 搜索命中折叠 / 未加载内容 | 展开相关过程并加载命中的内容，滚动到准确来源 | 查询词、owner 与覆盖范围说明 |
| 点击目录 | 定位请求、agent 回复或唯一任务入口；跟随当前阅读范围高亮 | 子任务和其子会话不重复成为两项；继承背景不进入自身目录 |
| 复制链接、刷新、后退 / 前进 | URL、内容 owner、页面标题与管理操作保持一致 | 可复现的 canonical 内容位置；父子导航不会留下另一会话的导出或恢复命令 |
| 读取更多 / 新记录到达 | 就地续读；新记录可用时提供可发现的入口 | 当前阅读锚点，避免强制滚到末尾 |

搜索契约首先覆盖“主会话或明确选中的子会话”。整个协作家族的跨会话搜索是后续能力，
只有实际提供完整范围检索时才能在 UI 中声称支持。继承背景保持单独范围，不混入上述结果。

## 6. 指标与证据语义

- 自身新增用量按本次执行拥有的请求计数；复制到子会话的历史 usage 记录不再次累计。
- 子会话实际发起的新模型请求，其输入（包括重新发送的共享背景）、缓存读入与输出仍是这次请求的用量。
  不能因内容相同而跨独立请求扣掉实际消耗。
- 总输入、未缓存输入、缓存读入和输出有清楚标签；缓存包含关系按 provider 归一化契约表达。
  缺少字段不当作零。请求合计与单次上下文长度分别呈现。
- “本会话”和“含子任务”分开；家族累计按 canonical 会话和拥有的请求计一次，展示覆盖情况。
  无法解析继承边界或关联缺失时，明确口径不完整，不能展示虚假的精确去重值。
- task 完成数不换算为目标完成百分比。没有结构化 goal 时，呈现原始请求即可。
- 原文、原文摘录、provider 明确记录、派生关系有可查询的区别。
  UI 不生成未经标识的“最新成果总结”，也不把不可解码返回替换成猜测正文。

## 7. 视觉、交互和实现边界

正文先于工具栏、指标和技术标签。左对齐、稳定行宽；中文长文、代码、表格分别使用合适的排版。
标题、操作、阅读正文采用清楚的层级；低频导出、管理和技术诊断收进次级菜单。
无协作的短会话自然退化为清晰的阅读页，不留下空关系框或空目标面板。

颜色之外还用名称、位置和文字状态表达关系。所有关键操作支持键盘，焦点可见；
折叠状态能被辅助技术读取。窄屏保留全部内容与导航能力，代码局部溢出不拖宽整个页面。
动效只解释用户触发的变化，并遵循 reduced-motion。

Provider 负责语义和证据归一化；共享阅读投影负责身份、归属、顺序和覆盖；浏览器负责布局与交互。
沿用 SSR、原生 JavaScript/CSS 和现有协议；只有实际消费者缺少事实时才扩展契约。
现有模型不能表达的呈现要求，先记录缺口及所有权，再实施，不能在浏览器里猜 provider 语义。

## 8. 可检查的验收场景

以下是重构完成的必验场景。通过自动化不替代用户对实页阅读与美观的验收。

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| P1 | 从会话库找到旧工作 | 通过可读标题、项目或搜索识别；过滤后进入阅读，再返回保留查找上下文 |
| P2 | 只有一问一答 | 首屏直接理解请求和回复，不被空框、过程工具栏或统计占据 |
| P3 | 多轮工具执行、未知 message phase | 已知过程默认收起且完整可达；未知文本不丢；reasoning 归属不串位 |
| P4 | 分派后主任务继续、两子任务并行 | 能辨认分派点与各自返回点；继续同一任务不产生重复身份 |
| P5 | 同一任务两次 follow-up、两次返回 | 四个不同来源分别可达；子侧完成与父侧接收不混同 |
| P6 | 打开、关闭、多级子历史 | 完整自身历史可读；父位置与焦点保留；无重复正文和 DOM ID |
| P7 | Compact、长保留上下文和 memory 产物 | 结果优先；续读到最后一条；无产出/加密说明准确；不虚构主上下文变更 |
| P8 | 子会话带共享背景 | 默认折叠；可完整续读；自身 ToC、搜索和新增 usage 不重复计入 |
| P9 | 长历史和延迟加载 | 后页长工具输出可被完整范围搜索命中并定位；未加载、部分覆盖和加载失败可区分 |
| P10 | 来源链接与浏览器历史 | 主/子来源刷新和后退后，URL、正文、标题、导出、管理、恢复操作 owner 一致 |
| P11 | 桌面、390px 窄屏、中英、明暗主题 | 正文与协作均可读；无全页横向溢出；键盘焦点、对比度和 reduced-motion 实测 |
| P12 | 各 provider、缺失记录与不存在的 child | 当前真实数据和 fixtures 分别注明；没有记录仍可理解，明确缺失而不补造关系 |

  收起依据实际阅读反馈决定。每个 provider 的真实样本验证不等于所有版本特性均已覆盖。
- **产品验收仍开放**：用户允许“先做出来看看”，不等于认可已完成的视觉设计。

发生产品选择时更新本文；发生视觉选择时更新视觉方向；每个切片将对应 P 编号、实页状态和验证结果
记录到相关专题，不在多个文档反复复制易过期的测试总数。改变已确认定位时更新决策记录。
