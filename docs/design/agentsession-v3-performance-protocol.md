## 执行与产物

[`scripts/v3-bench-matched.mjs`](../../scripts/v3-bench-matched.mjs) 使用私有 manifest 和
两个独立构建的 MCP 可执行入口，按固定顺序执行五次配对。每次使用新的 `tmp/` Viewer
状态，记录首次进程启动、索引与第一查询完成、九项查询的完整 cursor 遍历、同进程重复
首查，以及保留索引状态后的新进程就绪时间。查询输入含五个冻结 provider root 与固定
`updatedBefore`；启动前核对 2.0 基线提交、二者工作树提交、查询哈希和 Codex stat
签名，并对实际运行的包／binary 全部 `artifactPaths` 计算内容哈希；结束后复核全部
来源 stat 签名与产物内容哈希。原始记录、完整调用参数和失败保留在忽略提交的
`tmp/`；`summary.public.json` 仅含标签、签名、计数、资源和时延，所有十次尝试均计入。
九项搜索的完整有序结果语义哈希（包括 preview、title、directory 和其它 match 字段）
须在十次尝试间一致，且全部 provider 诊断为 `ok`；还须与独立生成的来源 golden
逐项匹配，才将 `searchSpeedupEligible` 置为 true。重复 session、重复 cursor、
有 cursor 的空页均判失败。此标志仅准许 **MCP 搜索**时延比较，不代表 Reader、
正文续读、用量归属或整体产品正确性已经通过。

独立 golden 由另一条读取/验证路径从冻结来源形成，格式为
`agentsession-v3-search-golden/v1`，含五个来源各自的 `providerStats`（文件数、
字节数、stat manifest SHA-256；非 Codex 来源还含内容 manifest SHA-256）和与九项输入同序的
`queries`；每项含 `label`、`querySha256`、完整分页 `count` 与
`orderedSemanticSha256`、`firstPageSemanticSha256`。首次进程和未变化重启的首查
均须与稍后的同查询首页及独立 golden 首页一致，才将就绪时延计入统计。
runner 不从本次测量结果生成 golden；缺失 golden 仍保存
原始测量，但退出为失败，公开报告中 `searchGoldenPassed=false`。
golden 还必须声明 `verification.status="source-verified"`；仅由 2.0 MCP
结果重复采集形成的 `candidate-unverified` 文件不会打开速度比较资格。
私有候选可用 `node scripts/v3-capture-v2-golden.mjs --output-dir tmp/v3-performance/<fresh-id>`
采集，包含逐页原始匹配和两次独立 MCP 进程的
复核记录。候选的计数与哈希重复一致只证明 2.0 输出稳定；来源验证仍须独立重建
完整匹配字段、顺序和正文片段。

私有 arm 配置 JSON 含 `v2`、`v3` 两项，各项需要绝对路径 `command`、`cwd`、
`artifactPath`、涵盖入口及运行依赖的 `artifactPaths` 数组，实际 Git 提交
`revision`、运行前冻结的 `artifactSha256`，以及 `args` 字符串数组。runner 在首轮
前核对该哈希，并在末轮后再次核对；不匹配即不进入速度比较。2.0 的 `artifactPaths` 至少包含 Viewer 与 MCP
两个构建输出目录和 lockfile；仅记录 MCP `cli.js` 不足以固定其导入的核心实现。参数中的
`{opencode}`、`{claude-code}`、`{codex}`、`{pi}`、`{deepseek-harness}` 分别替换为
manifest 中的来源路径；每个 arm 必须传入全部五项。`{metaPath}`、`{configPath}` 可
供入口显式指定隔离状态。2.0 的命令示例为绝对路径的 `node.exe`，首参数为独立
2.0 checkout 的 `packages/agentsession-mcp/dist/cli.js`，其后为五组 provider CLI flag
和上述来源占位符。3.0 的具体入口在可运行构建冻结后填入。运行命令：

```powershell
node scripts/v3-bench-matched.mjs --arms tmp/v3-performance/arms.private.json --golden tmp/v3-performance/search-golden.private.json --output-dir tmp/v3-performance/run-<unique-id>
```

当前 runner 仅覆盖 stdio MCP 搜索与进程就绪；OpenCode SQLite 文件及其同目录
`-wal`/`-shm` 伴随文件一并校验，非 Codex 语料的内容预扫描可能暖化 OS 文件缓存。
Web Reader 首段正文、来源变更刷新、
并行 Web/MCP、子进程总资源和物理磁盘读取尚需独立采集。MCP 进程退出码与信号由
当前固定版本 MCP SDK 的子进程句柄采集。MCP 传输字节是
请求/响应 JSON 载荷大小，不含 framing；进程资源在查询外取样，避免测量器影响单次
查询时延。只有对应正确性检查通过后，才可对这些其它负载作速度主张。
