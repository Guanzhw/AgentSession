# AgentSession 3.0：逐项验收输入映射

更新：2026-09-26。本文把 [3.0 验收契约](agentsession-v3-acceptance-contract.md) 的 56 个稳定 ID 映射到当前实际存在的输入。

这里的 **冻结** 指忽略提交的私有来源副本或已记录的 2.0 观察；**合成** 指仓库内 fixture 或测试现场构造的输入；**计划** 指尚未建立、需要另外冻结或构造的输入；**MISSING-SOURCE** 表示尚未取得的外部真实来源；**MISSING-SCENARIO** 表示可受控构造但尚未固定的场景输入；**TARGET-PENDING** 表示 S2–S4 才生成或执行的 3.0 受测产物与运行证据。一个 ID 可以同时有多种输入。旧测试和 2.0 观察可作为候选输入，不能证明 3.0 通过；本表只记输入，不关闭验收状态，也不把测试断言当作独立来源事实。

## 私有冻结输入角色

以下标签只描述语料角色，不包含 provider 会话 ID、原始路径或会话正文。副本及逐文件私有 manifest 在忽略提交的 tmp 目录中；公开来源与缺口说明见[冻结语料记录](agentsession-v3-corpus-plan.md)。

| 标签 | 当前冻结的输入角色 | 范围边界 |
| --- | --- | --- |
| F-CODEX-LONG | Codex 长历史，含 compaction 与 subagent 活动；浏览器基线角色为 long-team-compaction | 没有冻结的 Codex 压缩 JSONL 实录。 |
| F-DSH-PACKED | DSH native-v3-packed-compaction；同一来源保留 v0/v3 压缩代 | 代表压缩代选择和长历史；没有显式 team/workflow 记录。 |
| F-DSH-DESCRIPTOR | DSH 有记录的 subagent/descriptor 输入 | 不是原生 Teams 或 workflow 记录。 |
| F-OPENCODE-SQLITE | OpenCode 完整 SQLite v2 在线备份 | 有完整会话库；没有 fork_session_id。 |
| F-CLAUDE-BASIC | Claude Code 基础转录，26 条原始记录 | 不覆盖长历史、compact 或 sidechain。 |
| F-PI-BASIC | Pi 基础短转录；浏览器基线角色为 available-live | 不覆盖真实 branch 或 compact。 |
| F-FIVE-ROOTS | 上述五 provider 的冻结来源 roots，可验证可用性和对应格式读取 | 仅覆盖已选中的来源版本和样本，不等于五 provider 全格式覆盖。 |
| F-BROWSER | 冻结 2.0 桌面浏览器观察：Pi 短会话、Codex 长会话、DSH 压缩会话 | Codex 后段目录/来源跳转有已记录失败；这是缺陷对照，不是成功输入。详见[浏览器基线](agentsession-v3-browser-baseline.md)。 |
| F-META-PARTIAL | Viewer metadata 的私有 SQLite 副本 | 仅有一条 Codex metadata 行，不能覆盖星标、改名、排除等状态组合。 |
| F-META-STATE | 从上述副本生成的四份受控私有种子：功能对照/旧索引迁移 × 隐藏恢复前/后 | 覆盖元数据状态和退役行保留；新增标记是合成的，不是用户历史操作实录，也不证明 3.0 行为。 |
| F-V1-INDEX | 带 v1 派生 session_index 的 metadata 副本及隔离来源范围观察 | 可作为旧派生行保留/串用的迁移输入；不是完整迁移状态 fixture。 |
| F-V2-CAPTURE | 冻结 roots 上已抓取的 2.0 HTTP/MCP 响应与两种 MCP 客户端观察 | 记录在[交付计划](agentsession-v3-delivery-plan.md)；属于旧版观察，部分响应含私有身份，不能作为 source-verified golden。 |

S0 按以下**来源与受控输入**核对准备状态，S1 再形成独立 golden；每类记录来源 revision、canonical refs、预期事实和哈希，私有内容留在忽略提交的 corpus。现行真实来源无法取得的形状保留明确缺口，使用可验证的公开合成边界样本，不把合成样本记成真实覆盖：

1. 一个五 provider 的完整库/API/MCP 输入集：同标题双会话、父子家族、准确 event refs、搜索完整分页、导出末页和协议事实。
2. 补代表性真实来源角色：Codex 压缩 JSONL；DSH 原生 team/workflow；OpenCode fork；Pi branch；Claude 长 sidechain/compact。若真实来源不存在，维持缺口并分别保留已存在的合成负例。
3. 已有[元数据种子生成器](../../scripts/v3-build-metadata-seeds.mjs)及[测试](../../test/v3-metadata-seeds.test.mjs)覆盖 title/star/exclusion、v1 index 和退役行；补配套受控 config 文件。同一 seed 用于后续升级与回退前后摘要。
4. 同一输入的受控副本变更集：追加、重写、删除、坏尾行、Zstd generation 替换、SQLite/WAL 变化、双 roots 身份重叠及刷新失败/重启。为并发 Web/MCP 固定独立进程配置和 cursor。
5. 一个可续读到末页的长内容/协作/异步输入：多页 Markdown、工具与 reasoning、真实父子任务、exec/wait 返回或明确 unavailable；保存正文/引用末页摘要。

最终可运行的 3.0 包与目标平台 binary 属于 S2–S5 的**受测产物**。它们生成之后才执行安装、真实 stdio、性能配对和隔离服务检查；未生成不阻塞 S0 输入冻结，也不让相关 3.0 验收项提前通过。

本映射把来源样本和结构化边界测试分开列出。只有来源事实经独立核对，并为实现留下被测提交、准确调用、实际结果和限制后，才可按验收契约更新 U 状态。
