## 1. 产品目的与展示原则

AgentSession 的用户是开发者,打开它的目的:

| 目的 | 用户问题 | 对应界面 |
|:---|:---|:---|
| 找得回 | 那次会话在哪个工具里?什么时候?哪个项目? | 库 |
| 看得懂 | 聊了什么、做了什么、花了多少? | 详情页 · 对话(过程投影,非默认) |
| 理得清 | 工作做到哪了、谁(子代理)干的、上下文怎么变的? | 详情页 · 工作(默认) |
| 能复用 | 能不能继续、导出?总共消耗多少? | 详情页头部 · 检查器 · 统计 |

展示原则:

1. **以用户问题组织界面,不按后端结构组织**——投影只是数据来源,界面按问题重组;
2. **结构优先于罗列**——先给叙事与结构(目标是什么、做到哪了、图),细节按需展开;
3. **少即是多**——每屏一个主问题,默认只显示此刻需要的;
4. **语言自然**——说人话,没有记录就写"没有记录"。

## 2. 现有 UI 的三个痛点与对策

| # | 痛点(实测) | 对策 |
|:---|:---|:---|
| 1 | 工作图页不知所云,只是信息的罗列(goals 一段、tasks 十三行路径、relations 一堆 call_xxx 链接) | **叙事化**:目标是什么 → 做到哪了(进度一句话)→ 结构长什么样(图)→ 细节按需展开(任务表、交接)。废除原始关系行罗列 |
| 2 | 对话页是线性的,长会话(13 任务/13 子代理/10× 压缩,研究时点 2026-09-02)无法阅读 | **线程化**:按用户轮次分段,子代理活动折叠成卡,工具噪声折叠;保留"原文线性"切换 |
| 3 | 概览、原始数据两个标签不知道是干嘛的 | **概览取消**(元数据/消耗/操作并入头部与右侧检查器);**原始数据改名"事件"**,页首一句话说明用途 |

## 3. 信息架构

```
AgentSession
├─ 库(搜索 · 过滤 · 时间轴/列表)
├─ 详情页(从库进入)
│   ├─ 头部(共用):标题 · provider · 项目 · 时间 · 文件改动 · 操作(继续/导出/查找/上下条) · 恢复命令
│   ├─ 工作(默认):叙事视图(目标 → 进度 → 结构图 → 任务表)
│   ├─ 对话:线程视图 + 右侧检查器
│   └─ 事件:事件流,深挖入口
├─ 统计
└─ 设置
```

- 顶层导航:库 / 统计 / 设置(现状已有,继承)。
- 详情页三标签:**工作(默认)/ 对话 / 事件**;对话标签带右侧检查器,工作、事件全宽;
  已实现的 Work Graph-first 页面以五个透镜(Work/Execution/Coordination/Context/Evidence)
  组织默认工作视图,本文的标签划分是其信息设计延续;
- **对话与工作的分工**:对话页 = 过程原文(当时怎么说的、怎么做的、为什么);
  工作页 = 结果与结构(想做什么、做到哪了、谁干的、花了多少)。
  红线:工作页不显示对话原文,对话页不显示整体进度;子代理卡与压缩检查点属于过程事实,留在对话流;
- **页面连接(跳转图)**:
  - 库 → 详情页(点卡片);详情页 → 子会话详情(子代理卡/关系图/谱系),带"回到父会话";
  - 详情页 → 事件详情(任务证据按钮/事件流)→ 对话锚点(定位到对应消息);
  - 工作页任务行 →"在对话中定位":切对话页并滚动到该任务的工具调用/子代理卡;
  - 统计 → 带 provider/模型过滤跳回库;库/统计/设置平级;
  - 层级关系:库是索引层,详情页是单会话的三种投影(标签间互相锚定),子会话是同构递归,事件详情是最细粒度;
- 状态归属:列表过滤入 URL query,详情页当前标签入 hash,外观偏好入 localStorage;⌘K 全局跳转。

## 4. 各页面的展示信息与层级

层级约定:**主**(必见)/ **次**(扫读)/ **辅**(细看/悬停)/ **按需**(默认隐藏)。
"不默认显示"汇总见 §5。

### 4.1 库(会话列表)

- **顶部统计条**:提供方数 · 会话数 · 消息数 · Token 数;
- **每条会话**:
  - 主:标题;
  - 次:provider、相对时间、项目路径;
  - 辅:消息数、tokens、时长、压缩 ×N、子代理 N、artifacts N
    (现有 UI 已在卡片展示,实测用户关心,继承;三个信号建议合并为一行"信号条");
  - 悬停/操作:星标、批量选择;
- **搜索**:标题/内容/模型,跨全部提供方;
- **筛选 chips**:时间(今天/本周)、星标、有子代理;其余进"高级筛选";
- **视图**:时间轴(默认,按天分桶)/ 紧凑列表;
- **三态**:空库 / 无搜索结果 / 存储诊断(置顶一行,不打断列表)。

### 4.2 详情页头部(三标签共用)

- 主:标题;
- 次:provider、项目路径、开始时间、文件改动(+N −N,为 0 也如实显示);
- 操作(按优先级):**在终端中继续**、星标、导出 MD/JSON、在对话中查找、返回、上一条/下一条;
- 恢复命令单独一行等宽展示(继承现有"Terminal command")。

### 4.3 对话标签(过程原文 · 线程化;页内默认线程视图)

- **线程结构**(主):"线程"= 以用户轮次为根的会话树。每个用户消息是一个段头;
  段内按因果挂:该轮的助手回复(可多条)→ 回复下的工具调用(按序)→ 子代理分支(缩进卡)。
  推理附着在所属助手/工具下,不占层级;嵌套 ≤3 层(轮次 > 回复 > 工具/子代理),超过则折叠。
  与线性的本质区别:线性按消息到达顺序排,线程按因果归属排——子代理分支收进派发它的轮次,
  而不是散落在对话末尾;
- **agent 间长程通信不进主对话流**(规则):subagent 已演进为多 agent 协作——agent 之间
  有长程消息(message / mailbox-delivery / interrupt / handoff / result-delivery / acknowledgement),
  不再是一次性工具。主对话流只保留"用户 ↔ 主 agent"的活动与派发/交付锚点;
  agent 间往来收进 **agent 频道**(见 §4.6),否则长程消息会淹没主对话;
- **再次通信的轻量引用**(规则):主 agent 对既有 agent 的再次通信(非派发)在主对话流显示为
  一行轻量引用(如「→ ui-planner 发消息 · 10:31」),细节进频道——否则"主会话何时继续了这个
  subagent"在主流程不可见;
- **子代理活动默认折叠**(次):折叠成一张卡(子代理标题/状态/耗时/摘要),展开看摘要与"打开子会话"跳转;
- **工具调用**(次):编辑文件、执行命令这类展开标题行;状态行、小工具调用折叠成一行;输入/输出默认折叠、渐进加载;
- **推理**(按需):默认折叠,标注 token 数;
- **上下文压缩内联在流中**(次):合并为一个检查点,显示"压缩后上下文变成了什么"
  (现有 UI 的教训:同一次压缩被重复呈现);
- **右侧检查器**:会话信息(提供方/ID/模型/消息数/文件改动)、过程记录完整度(一行)、
  消耗(输入/输出/总计)、会话关系(父/子,**带关系类型标注**:分叉/接续/派生出,点击跳转,
  超 5 条给"谱系图"入口,有界 ≤9 节点)、记忆与经验资产区(按 scope 分组)、
  操作(继续/导出)——原"概览"标签的内容全部并入这里;
- **大纲**(左栏,可调宽):按线程结构列出用户轮次、任务、子会话树;`j/k` 移动、点击锚跳;
- **模式切换**(辅):线程(默认)/ 原文线性——短会话、导出对照用线性。

### 4.4 工作标签(结果与结构 · 叙事化)

按"阅读顺序"组织,而不是按数据域罗列:

1. **目标叙事**(主):目标标题 + 描述(取证据中的人类可读文本)+ 状态;
2. **进度一句话**(主):由任务状态派生的自然语言,如"13 个任务全部完成,目标仍在推进";
3. **结构图**(次):两层——①目标 → 任务的分层图;②**agent 协作图**:agent 为节点,
   边为协作关系(spawn/delegate/handoff/message 长程通道,标注消息数与方向),团队(team)分组;
   节点有界(≤9),给拓扑概览;
4. **任务表**(次,可折叠):任务名称(人类可读标题,回退到路径)/ 状态 / 耗时 / 证据按钮;
   超过 5 条折叠为"还有 N 个任务…";
5. **子代理交接**(按需):谁把活交给了谁(handoff/review);
6. **废除**:原始 relations 行罗列(call_xxx → session 链接)——由结构图和子代理列表取代。

### 4.5 事件标签(原"原始数据")

- 页首一句话:**"这个会话的每一条原始记录,按时间排列,用于核对和深挖。"**
- 事件类型分布(可点击过滤)+ 事件流(序列号/类型/摘要/原始·推断标识)+ 事件详情抽屉;
- 协议版本号、域覆盖状态、原始实体 ID 等细节放这里,不进主视觉。

### 4.6 异步任务与后台任务的展示

**多 agent 长程协作(subagent 已不是一次性工具)**:

- agent 生命周期:active(活跃)→ waiting(等待输入)→ interrupted(被打断)→ completed(结束);
  一个 agent 可以跨多个用户轮次存活。对话页用 **agent 卡**(取代一次性"子代理卡")展示:
  跨轮活跃区间、消息数、最后活动、当前状态;
- **agent 频道**:卡展开后是该 agent 的长程通信时间线——message / mailbox-delivery / interrupt /
  handoff / result-delivery / result-acknowledgement,按时间排列、默认折叠;
  主对话流只保留派发与交付锚点,通信细节不进正文;
- 双锚不变:卡挂在派发位置(因果锚),卡内显示真实时间与"结果于 10:42 到达"(时间锚);
- 无子会话的后台 run 同样双锚:挂在派发它的工具调用/消息处,结果交回时更新该卡状态,不另起位置;
- 后台任务形成资产(memory 等):任务同时出现在工作页任务表(它是工作)与检查器资产区(它是产物),
  资产条目带"触发位置/来源任务"链接,两者互跳;
- 结构图:任务图之外加 **agent 协作图**(谁和谁长期通信、消息数),异步派发用虚线边;
- token 归属:direct / inherited / shared 三分(协议已定义;当前无 provider 记录
  来源切片,投影未暴露时 UI 只显权威总量——见 §7 与 work-graph 规格 Evolution backlog)。

**后台任务**:

- 压缩 compact:过程事实 → 对话页内联检查点(合并呈现,显示压缩后上下文变成了什么 +
  before→after tokens);完整列表在事件页,不重复;
- 记忆/经验/用户信息(memory/experience/user-info):长期资产,不是过程 →
  检查器新增"记忆与经验"折叠区,按 scope(session/agent/project/user/org)分组,
  只列标题+摘要(metadata-first),内容按需展开;
- 检查点/整理(checkpoint/dream/reinjection):改变上下文的过程 → 对话页按影响内联 + 事件页完整列表;
- 原则:后台任务分两类——"改变上下文的"进对话流(检查点)+ 事件页列表;"长期资产"进检查器资产区。

**资产与环境(项目级)**:

- 项目级资产:`ContextArtifact` scope=project 的 memory/experience/user-info →
  检查器资产区"项目"组,列出该会话所在项目形成的记忆/经验(标题+摘要,metadata-first);
- 启用清单(skill/plugin/hook):会话"启用了什么"不是独立的协议事实,来源只能是
  系统提示词证据(可解析来源,带路径与 resolution 元数据)或 artifact kind=skill;
  资产区"环境与工具"组如实标注"已解析来源"与"不可用",不编造清单;
- 环境重载(插件/skills 热更新):协议没有专用事件种类;provider 若记录了,落在
  context/control/unknown 事件里,事件页按类别过滤可见。结构化呈现需要协议新增
  normalized kind(如 environment.reloaded)——已记入
  `docs/specs/runtime-protocol-workbench/design.md` §10 backlog(协议演进议题,UI 不发明)。

### 4.7 八个典型场景走查(验收标准)

1. **compact 的位置与压缩后上下文**:对话页线程流中,触发处一个检查点卡(before→after tokens +
   压缩后上下文摘要);展开看结果详情;完整列表在事件页。来源:context 投影 transformation + 事件;
2. **subagent 的创建/首次返回/再次继续**:创建处挂 agent 卡(状态"已派发");首次结果交回时卡上
   显示"结果于 T1 到达"+ 状态"已交回";主 agent 再次通信时,主流程出现一行轻量引用
   (「→ ui-planner 发消息」);完整双向序列在 agent 频道时间线(创建 → 首次返回 → 继续 → 交付/确认);
3. **形成 memory 的后台任务**:工作页任务表有该后台任务一行(状态/时间/证据);检查器"记忆与经验"
   资产区有该条记忆(带来源任务链接);两者互跳;
4. **后台进程的创建/结束/返回**:有子会话 → agent 卡(挂派发处,结果交回时更新状态与时间);
   无子会话 → 挂在派发它的工具调用/消息处,同样更新;工作页任务表显示完整时间区间。

若 provider 未记录对应 observation(如 mailbox-delivery),UI 显示"没有记录",不猜测。

5. **项目级资产与启用清单**:检查器资产区"项目"组看项目级 memory/experience;
   "环境与工具"组看 skill/plugin/hook(来源标注 resolved/unavailable);
6. **harness 环境变化(重载)**:事件页按 context/control/unknown 过滤;结构化程度取决于
   协议是否新增环境事件种类;
7. **会话派生关系(fork)**:检查器会话关系区,行带类型(分叉自/接续/派生出),点击跳转;
   超 5 条给谱系图(有界 ≤9 节点);
8. **文件改动与 git**:头部与检查器显示文件改动统计(已有,继承);会话 ↔ git commit
   关联为可选增强能力,见开放问题。

### 4.8 统计

会话分布按提供方、Token 趋势(14 天)、模型排行、数据源状态(在线数/索引新鲜度,一行式)。

### 4.9 设置

主题(深/浅/跟随系统)、密度(舒适/紧凑)、数据目录等既有配置项。

## 5. 层级与克制规则(默认不显示清单)

| 信息 | 放哪 |
|:---|:---|
| 协议版本号、域覆盖状态 | 事件标签 / 事件详情 |
| 原始实体 ID | 任务行的证据按钮、事件详情 |
| 事件流 | 事件标签(对话/工作页不出现) |
| 存储诊断 | 库页顶部一行;正常时不显示 |
| 推理、工具输入输出 | 默认折叠,点击展开 |
| 子代理活动 | 默认折叠成卡 |
| 文件改动 | 头部一行;为 0 时如实显示 |

空态语言示例:"没有记录"、"这次会话没有子代理"、"该提供方未连接,数据不可用"。

## 7. 数据来源映射(后端 → 展示)

| 展示信息 | 数据来源 |
|:---|:---|
| 列表卡片(标题/时间/项目/统计/三信号) | 启动索引 + 会话摘要 |
| 消息、工具、推理、token | 消息兼容投影(渐进加载 API) |
| 目标/任务/运行/请求用量 | 工作图 work/execution 投影 |
| 进度一句话 | 任务状态派生(前端呈现层,不进协议数据) |
| agent 频道(消息/信箱投递/打断/交接/交付+确认) | `CoordinationObservation.kind`(message / mailbox-delivery / interrupt / handoff / result-delivery / result-acknowledgement)+ state + sender/recipient + 锚点 |
| agent 卡生命周期、跨轮活跃区间 | `AgentRun` 状态/时刻 + observation 时间戳 |
| agent 协作图(team 分组) | `Actor`(kind=team、teamId、memberActorIds)+ observation 边 |

## 8. 与现有 UI 的继承清单(实测 127.0.0.1:3456)

**继承**:

- 列表卡片字段:标题/provider/相对时间/项目路径/消息数/tokens/时长/压缩×N/子代理N/artifacts N;
- 详情页头部:星标、在终端中继续、导出 MD/JSON、在对话中查找、上一条/下一条、Terminal command;
- 工作图数据:计数条、任务行+证据按钮、目标文本;
- 概览页内容:创建/更新/目录/文件改动/会话 ID/导出(并入检查器与头部);
- TOC 可调宽、会话内搜索、主题切换、无限滚动。

**重组(针对痛点)**:

- 工作图五透镜罗列 → 叙事化四段(目标/进度/图/任务表);
- 线性对话 → 线程视图(默认)+ 线性切换;
- 概览标签 → 取消,内容并入检查器与头部;
- 原始数据标签 → "事件",加用途说明;
- 协议术语 → 人话;原始 ID 收进证据/详情。

**丢弃**:原始 relations 行罗列(由结构图取代)。
