# AgentSession 视觉方向与参考

状态：用户已选择样稿 3，正式页面实施中；实页验收开放。更新：2026-09-17。
内容与交互以[产品呈现规范](runtime-presentation-contract.md)为准。本文件记录为什么这样设计、
借鉴哪些案例以及资源怎么用；具体视觉必须在真实历史页面中验证。

## 1. 设计简报

面向回看 coding agent 工作的用户，先让人读懂请求与交付，再按需深入执行过程和后台协作。
本轮重做会话库和历史阅读页的视觉及交互层级，并将同一套基础样式应用到统计与设置。
已有 provider 证据、完整阅读、异步来源定位和搜索能力继续作为基础。

视觉主题：**有来路的工作记录**。最有辨识度的部分是正文中的局部协作关系：
读者看到任务从哪里分出去、带什么结果回来，同时仍然读得到完整历史。
页面的其余部分保持安静，给长时间阅读留出空间。

## 2. 案例与采用理由

以下结论来自已读取的公开官方资料；属于设计参考，不代表我们已验证目标产品的全部交互。

| 参考 | 观察到的做法 | AgentSession 采用方式 |
| --- | --- | --- |
| [Linear：2026 年界面更新](https://linear.app/now/behind-the-latest-design-refresh) | 降低导航权重，统一头部位置，减少多余图标背景和边框 | 导航退后、正文前置；统一标题/搜索/菜单位置；用留白和字重区分层级 |
| [Linear：2024 年重设计过程](https://linear.app/now/how-we-redesigned-the-linear-ui) | 协调整个外壳、侧栏、标签与面板，而非逐块孤立美化 | 会话库与阅读页使用同一套布局和交互规则，同时保留不同页面的任务密度 |
| [GitHub Actions：运行关系图](https://docs.github.com/en/actions/how-tos/monitor-workflows/use-the-visualization-graph) | 可视关系与状态关联，点击任务进入执行日志 | 关系可视化与准确原文互相定位；图是理解入口，完整历史仍为主阅读面 |
| [Radix：颜色刻度](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale) | 背景、交互状态、边框和文字有不同语义级别 | 将现有主题收敛为少量语义 tokens，明暗主题维持相同的信息层级 |
| [shadcn/ui Blocks](https://ui.shadcn.com/blocks) | 可组合的侧栏、布局和数据界面示例 | 用来比对布局、密度和状态完整性；在现有 SSR/原生 JS 中实现需要的模式 |

本次实际页面观察提供了明确的修改输入：会话库有大量 UUID 标题和多徽章元数据；
阅读页先展示长标题、多项操作、重复标题、目录与关系选择控件，之后才开始请求正文。
保留完整阅读能力的同时，应降低这些辅助信息的视觉权重。

顶部导航、连续正文、按需打开的右侧任务面板。下面的 tokens 是实施基线，最终按选定样稿和实页对照调整。

### 已选方向：正文与按需任务侧栏

- 正文是完整历史的主入口，用户请求和 agent 回复通过排版、间距与轻分隔组织。
  工具和推理保留折叠入口，子历史仍可在正文附近完整展开。
- 右侧栏命名为“任务与协作”（Tasks & collaboration），默认收起；正文协作节点可打开并选择对应任务。
  无协作记录的会话不显示空面板。目录作为可收起的阅读导航，不与右栏同时常驻挤压正文。
- 侧栏先展示实际任务的关联概览，选中后显示分派、追加要求、中断/继续和各次返回的记录序列。
  每个记录均可定位准确正文或来源；完整子历史在正文阅读，侧栏只提供关联与入口。
- 同一任务多次返回保持同一身份，子侧完成与父侧接收分别标注。连线表示记录支持的关系，
  不以距离暗示运行时长，不把最后已知状态当实时运行状态。
- 样稿中的“导航审查”是合成子任务名，含义是检查子会话打开、关闭和返回行为，
  不是固定产品栏目。真实页面使用记录中的任务名与目的摘录，不复制样稿内容。
- 窄屏将侧栏作为可关闭的全宽检查层；关闭后恢复正文位置与触发焦点。
  操作、语言和主题沿用正式产品，不另外建立只能展示合成内容的页面。

## 4. 候选视觉系统

### 颜色：冷静的中性底色，一种关系强调色

保留现有冷色工具型产品的连续性，移除装饰网格，减少重复描边和同权重徽章。
这是待截图验证的起点；正文/控件/焦点对比度必须在两种主题中实测。

| 语义 token | 浅色候选 | 深色候选 | 用途 |
| --- | --- | --- | --- |
| Canvas | `#F6F7F9` | `#171B22` | 页面外壳，安静后退 |
| Surface | `#FFFFFF` | `#202630` | 阅读层、菜单和展开子历史 |
| Ink | `#202832` | `#E7EDF4` | 正文、主标题 |
| Muted | `#586777` | `#A6B2C2` | 次级信息，仍可阅读 |
| Divider | `#D4DCE5` | `#465262` | 必要分隔，避免每段围框 |
| Relation | `#245BCC` | `#99BAFF` | 当前任务、来源定位、键盘焦点 |

成功、错误等状态沿用并校验现有语义色；每个状态同时有文字或图标说明。
任务身份主要靠名称与位置辨认，不能为几十个任务依次分配难区分的彩虹色。

### 字体与节奏

- 中文与界面使用系统 UI 字体：`Segoe UI`、`PingFang SC`、`Microsoft YaHei UI`、系统 sans-serif。
  选择依据是本地可用、中文长文清晰和低加载成本；不是把英文品牌字体强加给正文。
- 正文候选 16px / 1.75；次级信息 13px / 1.5；标题 24px / 1.35。
  最终依据桌面与 390px 的同内容截图调整。
- 代码沿用等宽字体，只在代码、命令和精确 ID 里使用；普通导航、时间和提示不使用等宽标签风格。
- 正文左对齐；英文一般不超过 80 字符/行，中文以约 32–42 字/行试排。
  宽表格和代码使用局部宽容器，不迫使整篇正文拉长。
- 基础间距取 4/8/12/16/24/32px；同一回复内部紧凑，用户请求之间留出清楚的段落空间。

### 布局候选比较

以下仅是区域关系草图，不是 UI 资产或最终视觉稿。

```text
A  阅读为中心：候选基线
┌ 导航 ┬ 返回 / 简短标题                 搜索  菜单 ┐
│      ├ 目录 ┬ 用户请求、agent 回复                  │
│      │      │   ├ 分派任务                         │
│      │      │   │ 主任务继续                       │
│      │      │   └ 返回结果  [展开子历史]            │
│      │      │ 执行过程（收起）                     │
└──────┴──────┴──────────────────────────────────────┘

B  阅读 + 常驻关系面板：用于比较
┌ 导航 ┬ 正文                         ┬ 任务关系     ┐
│      │ 请求、回复与过程               │ 时间/分支    │
└──────┴───────────────────────────────┴─────────────┘
```

A/B 是生成样稿之前的布局比较，已由样稿 3 的选择收敛：保留 A 的局部正文关系，
将 B 的关系概览做成按需打开的右栏。完整历史始终保留。

选定方向的实施尺寸：顶部导航 64px（窄屏 56px）；正文以 74ch 为独立阅读上限；
打开任务侧栏时，整体阅读区域上限 1180px，侧栏 360–430px。目录在正文前按需展开，
内部最多占用 240px，不保留空白导航列。低于 1100px 时任务侧栏改为可关闭检查层，
保留正文行宽。实际中文段落而非其外层容器使用 16px 字号。
窄屏子历史展开为全宽阅读层，以明确来源和返回动作替代层层缩进。

### 控件与状态

- 头部主动作是查找与导航；导出、收藏、继续执行、管理等按频率与风险分层，避免整排等重按钮。
  具体动作仍可发现，菜单不能成为隐藏所有功能的黑洞。
- 阅读消息主要由排版和间距分隔；子历史有轻量边界以区别 owner，不能每个工具/消息套一层卡片。
- 协作节点用任务名、动作、可读结果摘录说明意义；精确时间、内部路径与来源 ID 按需展开。
- 同一任务的往来序列将连续普通消息局部折叠，分派、追加要求、中断和各次返回继续可见；
  展开后每条消息的原文来源仍独立存在。完整子历史入口放在往来序列之前。
- 折叠、加载、失败、空记录、部分记录、选中和焦点状态在设计稿中一起给出。
- 仅对用户触发的展开和定位提供短暂反馈；不循环闪烁历史状态，不自动播放装饰动画。

## 5. 写代码前的自审

| 风险 | 本轮取舍 |
| --- | --- |
| 把所有内容装进相同卡片，看起来像通用仪表盘 | 正文连续排版；容器只用于真正不同的 owner 或临时检查层 |
| 新增一张大关系图，再次让用户找不到会话 | 保持正文主路径；图和时间概览按需展开并可定位准确正文 |
| 为追求干净删掉过程、历史或错误 | 折叠而非丢弃；完整性与覆盖规则由产品规范约束 |
| 只把旧界面换颜色，信息仍难理解 | 同时重做标题、头部动作层级、任务目的/结果表达及协作交互 |
| 用英文工具标签代替用户意义 | UI 先回答“谁在做什么、带回什么”；技术字段只用于进一步查证 |
| 引入一套组件框架造成维护成本 | 沿用项目无运行时依赖、SSR 和原生脚本；只借鉴所需模式 |

## 6. 分阶段执行与验收产物

1. **明确规格**：提交产品内容矩阵、关系语义、导航行为、案例来源与本文视觉候选。状态：本次文档切片。
2. **选择视觉目标**：基于会话库、普通阅读、异步协作和展开子历史四种实际状态，给出视觉候选；
   使用相同的可读内容比较。状态：用户已选择对话中第 3 张阅读页样稿。
   当前样稿使用合成历史，未实现交互；会话库和其他状态需在选定方向后补齐。
3. **首个真实切片**：先做会话库及同一个真实 session 的阅读闭环，验证查找、协作、完整子历史和返回。
   同步中英文、明暗主题、窄屏和键盘；展示可操作实页。状态：方案 3 的正式 Reader 首个可操作切片已通过工程验收；会话库与整体视觉验收继续推进。
4. **扩展与替换**：覆盖长历史、上下文结果、重复返回、嵌套协作、错误/缺失和所有当前 provider；
   统一统计/设置的基础样式，移除已被替代的布局规则。状态：后续切片。
5. **交付检查**：对照选定样稿与同视口实页，检查完整阅读能力和产品规范 P1–P12；
   工程验证、用户反馈与尚未验证的内容分别记录。状态：开放。

2026-09-17 工程检查：704 项测试、七个 provider 真实 API 样本、整站 E2E、
Windows binary smoke 通过。真实子历史展开、刷新后返回、来源定位、桌面明暗主题、
320/390px 窄屏已检查。实际页面与样稿 3 同视口比对后，仍需收敛紧凑任务概览、
任务目的与返回摘录和元数据密度；本轮不将样稿选择等同于整体验收。

每个视觉切片保留 viewport、主题、语言和页面状态明确的前后截图；真实私有历史截图放在忽略的本地目录，
公开文档仅使用合成样例或已获准的素材。最终视觉验收依据实页，不依赖本文形容词或测试数量。
