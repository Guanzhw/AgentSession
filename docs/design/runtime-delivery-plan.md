## 9. 每阶段如何汇报与提交

### 信息与呈现方式的对应原则（用户补充，2026-09-20）

先明确用户要理解的问题，再选择展示方式。图负责关系，时间线负责过程，正文负责内容；
任务目录与搜索结果使用可扫描的列表，不能把列表当成协作关系的最终呈现。

| 信息 / 用户的问题 | 主要呈现 | 展开后的内容 | 阶段归属 |
| --- | --- | --- | --- |
| 主会话说了什么、最后得到什么 | 连续对话正文，按请求/回复组织 | 该轮执行过程和完整输出 | 1 |
| 谁负责什么、与谁合作 | 有名称、职责和方向标签的任务/成员关系图 | 选中节点或边的往来时间线及正文 | 2、4 |
| 何时分派、追加、完成、收到结果 | 局部事件时间线，关联主线对应位置 | 每次具体要求与结果 | 2 |
| 哪些工作并行、后台何时分离和返回 | 共用时间轴的主线/后台泳道，分离与返回连线 | 命令、输出、密集轮询明细 | 3 |
| compact 后保留什么、生成了什么 memory | 结果内容卡片，保存节点落在主线相应位置 | 生成/后续整理过程；确有前后文本时才提供差异 | 1、3 |
| 如何找到一段历史或一个任务 | 可搜索的会话库、任务目录和命中摘录 | 定位到原文；图同步选中对应对象 | 2、5 |
| 用量变化、不同项占比 | 趋势图/分布图和少量汇总数 | 精确数值表及口径 | 5 |
| 设置与技术原始内容 | 分组表单；按需代码/结构化字段 | 完整配置或原始记录 | 5 |

图中保留稳定的节点位置和明确的边语义；大量对象按任务或时间范围逐步展开。图和列表
共享同一选择状态，图中的每个关系最终都能进入对应内容。普通问答不需要空关系图。
验收时分别检查“看懂关系”“看懂顺序”“读到完整内容”，不能只验证图是否画出来。

每次工作汇报固定包含：**当前阶段/子项、这次已完成、还缺什么、下一动作**。
完成一个阶段时提供：

1. 可以直接打开的实际页面和 3–5 步阅读路径。
2. 针对本阶段的前后截图或简短操作演示。
3. 已通过的验收项及具体缺口；用户视觉反馈单列。
4. 对应提交与推送结果、远端 CI 结论。

按既有授权分阶段提交并推送，不将多个未验收阶段堆成一个巨型提交。小修与所属阶段一起
审查；跨模块、provider 或协议变化按风险安排独立审查。新问题归入对应阶段，直接破坏
当前交付的缺陷在当前阶段解决。已有响应式行为保留，后续只做桌面验证。
