# 正文旁的成员侧轨

2026-09-22：用户已试读并认可真实历史交互样稿，正式 Reader 接入及桌面验收完成，发布状态见交付计划。

## 内容与形式

正文是主 Agent 的主线。右侧窄区域只放成员轨道，与正文共享纵向位置和滚动；左侧目录保留。
轨道按成员身份固定颜色与顺序，名称在对应轨道上保持可见。正文仍以请求、回复和关键协作内容
为阅读核心，模型与用量保持紧凑直显。

| 信息 | 呈现 |
| --- | --- |
| 创建成员 | 从正文发生位置指向该成员轨道的起点 |
| 成员间消息 | 从发送成员的空心节点，连接到接收成员的实心节点；箭头指向接收端 |
| 返回主 Agent | 从成员的发送位置指向正文实际收到消息的位置 |
| 派遣后主线继续 | 正文照常阅读，成员轨道从旁连续经过 |
| 消息与完整子历史 | 点击节点展开对应原文；原有完整子历史入口与关闭返回保留 |
| 多成员 | 正式 Reader 保留全体成员选择器，默认显示附近最多四名成员；选中远处成员会定位到其第一条记录 |

发送和送达必须由明确的同一消息 ID 配对；送达不能画成另一条回复。返回主 Agent 使用明确
的主会话身份，绘制位置为正文边缘，不为主 Agent 新增一列。颜色编码成员身份，不编码状态。
节点仍提供可聚焦链接、成员名与可访问方向说明，视觉上不重复占用一行方向文字。

成员按本文首次出现顺序分配六色，前六名不发生颜色碰撞；更多成员循环使用色板，始终配合
轨道名称识别。成员选择与滚动不改变同一本文中的颜色。当前窗口最多绘制 80 条关系；跨窗口
长连线按可见区裁剪，保留真实端点，裁剪边界不伪装成发送或送达节点。

纵向距离表达正文阅读顺序，不表达实际耗时。执行折叠时节点对齐所属可见执行入口，展开后
回到原记录；异步内容加载和子历史展开同样需要重新测量。没有明确终止记录时不画结束节点，
虚线尾部只表明轨道在本片段之外仍未得知终态；idle 与单轮结束都不等于成员终止。

只有收到记录而缺少单独发送记录时，已知发送成员到正文/接收成员的箭头仍可呈现，
实心节点落在实际接收位置；不增加一个虚构的发送时刻。
