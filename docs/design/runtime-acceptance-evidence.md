### 往来记录的显示顺序（P5）

同一任务中，14:44 的跟进显示在 14:43 的父侧接收之前；子侧两次完成又被放在所有父侧接收之后。
来源时间本身可用，问题在 Reader 消费了按来源批次构造的数组顺序。修复属于共享 Reader 投影，
不改变 provider 原记录。修复后排序、完整集合状态摘要和续页完整性均已验收，
包括 120 条三页、已读前缀变化、正常后缀新增的回归。

### 子会话的页面操作归属（P10，已修复）

从目录打开没有就地分派锚点的相关子会话，会替换阅读正文并更新 canonical URL。
真实浏览器中，页面主标题、MD/JSON 导出链接，以及恢复、重命名、复制 ID、删除按钮仍指向父会话。
刷新同一 URL 后才全部成为子会话。验证只读取链接和按钮属性，没有执行修改或恢复操作。

这一结果推翻了“页头始终保留最初会话 owner 即可”的假设。需要让页面操作 owner 与当前 URL 的
含义一致，同时保留就地子历史与父阅读位置。不能通过更改验收文字把这个冲突视为通过。

实际修复统一了目录和协作入口：相关子历史保持就地打开，pathname、标题和全局操作共同属于根页面；
`readerSource` / `readerAncestor` 复现所选子来源。没有分派位置时明确标注，单独阅读才完整切换 owner。
真实父会话的 SQLite 查询、196 条结果和已展开工具保留，关闭后恢复到启动位置与控件。
三层来源复制到新页、刷新及逐级关闭通过；另一真实会话的子完成事件刷新后，Back 回到父侧接收记录。

首次并发 API 检查发生一次 `ECONNRESET`；服务进程仍在线且错误日志为空，重试完整通过。
七个 provider 的样本均无协议校验错误；OpenClaw 和 Pi 为本地安装 smoke 记录。
全套测试、整站 E2E、独立审查和 Windows binary 检查通过，数量及执行记录见
[Reader 检查点](runtime-reader-slice.md)。浏览器暴露的缺失客户端翻译已补齐并增加回归。

### 超长活动会话加载（P9，开放）

超长活动 Codex 会话的完整 API 请求等待超过四分钟，同期页面导航超时；进程仍在线、
CPU 持续增长且错误日志为空。该请求随后被部署重启中断，因此最终连接重置不是自发崩溃证据。
较小真实会话已通过上述验收，但不能替代这个性能场景。

独立进程的分段诊断已区分两个问题：冷元数据索引读取 535 个文件、约 2.24 GB，耗时
8.0 秒；随后完整 scan 耗时 209.3 秒、读取约 59.66 GB，其中约 56.57 GB 是同一个
432 MB 父会话的重复读取。已有任务边界的子会话不需要父正文来判定归属，重复读取
来自消费路径，而非源数据规模本身。旧 tree/container 缓存还把构建时间计入一秒有效期，
导致慢构建结果立即失效。

修复后，另一次 535 条真实会话 scan 耗时 15.1 秒、读取约 4.16 GB；同一个父文件的
累计读取约 2.16 GB。两次观测之间活动记录继续增长，因此不是完全相同输入的基准。
确定性回归验证有任务边界的子会话不加载父正文，旧 fork 仍读取父证据，并保留继承
背景、来源 ID、token 归属以及 v2/v3 对继承原始事件的过滤。

稳定真实九子任务会话的 tree、container、metrics 序列化 SHA-256 在修复前后分别完全一致。
超大会话的独立 tree 构建耗时 8.7 秒，紧接的 container 命中缓存、未读取文件；metrics
耗时 5.5 秒。生产服务重启后的 Codex 索引为 535 条 / 28.0 秒。七 provider 的常规
Reader/page/preview/API、四项 404、整站 E2E、真实子历史展开和返回、763 项测试及
Windows binary smoke 通过。

上一检查点的超大会话完整 API 未通过：`JSON.stringify` 抛出 `Invalid string length`，
随后错误响应尝试修改已经发送的响应头，连接被关闭。进程仍在线，后续常规检查通过。
这条接口同时返回 messages、tree 和 container；问题属于完整响应的字符串构造。

随后改为保持原五字段合同的有界流式序列化。稳定真实会话的 compact API 和 pretty JSON
导出均与修改前逐字节一致。原失败的活动根会话现返回约 722 MB API 和 720 MB 导出，
独立流式解析器分别在 29.5 / 28.5 秒内读到完整 JSON 结尾，后续健康检查为 7–10 ms。
重启后的服务日志无序列化或重复响应头错误。两个大响应之间活动数据继续增长，且导出
消息投影不同，不用其相互字节差异推断内容丢失。见
[流式决策](../../.agents/decisions/implemented/2026-09-17-large-session-json-streaming.md)。

### P10 原生来源跳转与独立阅读位置（2026-09-19）

同页原生片段导航创建新的浏览器记录。Reader 现在直接登记该记录的独立身份和空阅读位置，
首次按来源定位；后退和前进恢复各条记录后来读到的位置与焦点。登记采用 `replaceState`，
不额外创建浏览器历史。已知身份保持稳定，首次访问更早的未登记条目后，新导航也不会覆盖它。
