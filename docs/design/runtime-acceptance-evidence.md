## 本轮真实缺陷

### 往来记录的显示顺序（P5）

同一任务中，14:44 的跟进显示在 14:43 的父侧接收之前；子侧两次完成又被放在所有父侧接收之后。
来源时间本身可用，问题在 Reader 消费了按来源批次构造的数组顺序。修复属于共享 Reader 投影，
不改变 provider 原记录。修复后排序、完整集合状态摘要和续页完整性均已验收，
包括 120 条三页、已读前缀变化、正常后缀新增的回归。

### 子会话的页面操作归属（P10）

从目录打开没有就地分派锚点的相关子会话，会替换阅读正文并更新 canonical URL。
真实浏览器中，页面主标题、MD/JSON 导出链接，以及恢复、重命名、复制 ID、删除按钮仍指向父会话。
刷新同一 URL 后才全部成为子会话。验证只读取链接和按钮属性，没有执行修改或恢复操作。

这一结果推翻了“页头始终保留最初会话 owner 即可”的假设。需要让页面操作 owner 与当前 URL 的
含义一致，同时保留就地子历史与父阅读位置。不能通过更改验收文字把这个冲突视为通过。
