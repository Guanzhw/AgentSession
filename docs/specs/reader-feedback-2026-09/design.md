# Reader 反馈修订：实施设计

更新：2026-09-23。需求与设计问题见 [requirements](requirements.md)，状态见 [tasks](tasks.md)。

## 1. 视觉与组织

沿用用户确认的正文加成员侧轨。正文是视觉焦点，颜色只帮助识别成员，边框只表达包含关系。
沿用 `reader.css` 现有明暗主题、字体与成员色板；本次不重新换肤或引入素材库。
用户块靠右，Agent 正文靠左；过程入口与所属正文同一阅读宽度；子历史接在原卡片内。
不通过缩小正文字号提高密度，而是消除重复标题、双层入口与无意义空白。

## 2. 阅读连续性（F03–F05）

- 右对齐作用于用户消息块与元信息，不对段落、代码或表格使用右对齐。
- 来源只有一个“查看事件详情”动作，名称对应现有事件详情目标；其中保留实际原文入口。
  来源锚点与 owner 保持，不为无内容的折叠增加一层界面，也不在视图解析 provider 原始类型来命名。
- 从协作卡片打开 child，挂载到该卡片自己的 body 内。一级展开避免重复父面包屑和 child
  标题；多级导航、独立打开、关闭返回仍提供。点击原入口可收起。
- 父卡片样式、侧轨选择和点击处理只能作用于所属 Reader pane；不能把子历史里的卡片染成
  父成员颜色，也不能把子正文点击解释为选择父任务。

拥有文件：`src/views/reader-coordination.ts`、`src/static/app/session-reader.js`、
`src/static/app/reader-relations.js`、`src/static/reader.css`、两种 locale。

## 3. 相邻过程集中（F08）

定义“连续过程段”：前一条消息最后一个可见内容是折叠执行过程，后面紧接纯过程消息，
中间没有用户内容、可读 Agent 文本、关键协作节点、错误/注意事项或上下文变化。
连续过程段默认只有一个入口；展开后保留原始消息边界及具体工具。

优先在服务端阅读呈现层组合，不使用浏览器正则解析 HTML 去猜消息语义。
尾部过程属于原消息，后续请求仍属于后续消息。组合摘要准确计数各条过程，不重复显示或累计
已在前一条 Agent 信息栏显示的 usage；多模型分项和最后上下文值延续现有契约。
为组合后的内容保留原锚点，导航与搜索命中能打开需要的折叠并定位。

实现调查若发现现有 `ConversationItem` 无法表达该边界，应增加最少的呈现字段，而不是
另建 provider turn、二次协议或 DOM 后处理兼容层。

拥有文件：`src/views/session.ts` 及其呈现测试；只在必要时同步加载/搜索控制器 hooks。

## 4. 侧轨稳定性与容量（F06/F07/F09）

确定的不变量：

1. 一个成员在当前 Reader 中身份与颜色固定；主 Agent 使用正文边缘，不新增主轨。
2. 视口裁剪只改变 overlay。卡片样式与文档坐标不由当下入选成员决定。
3. 仍显示的成员不因其他成员进入/离开而横向换列；明确选择才改变聚焦对象。
4. 视口内真实事件的关联优先于远处旧成员的未知尾部；容量不足有可发现的处理方式。
5. 父/子 pane 各自测量与绘制。展开、延迟加载、字体/窗口变化可重新测量；单纯滚动不重排正文。
6. 发送、送达、创建与返回均使用已记录端点；未知结束不能被画成已结束或持续在线。

Q1/Q2 已确认：使用窄侧轨、稳定槽位与当前事件优先；容量外的关系提供紧凑成员聚焦入口，
选择时切换关联显示，正文形状保持。轨道止于最后一次交互，不绘制未知尾部；新增交互读入后
才延续。线的终点表达当前历史的交互范围，完成/退出等文字状态继续使用归一化记录。
保留 80 条可见边的构造边界，不通过每次绘制全量巨大 SVG 解决稳定性。

拥有文件：`src/static/app/reader-member-rails.js`、`src/static/reader.css`、
`src/views/reader-member-rails.ts` 及必要的 locale；共享数据投影只在真实消费者缺字段时改变。
既有 [侧轨决策](../../../.agents/decisions/implemented/2026-09-22-reader-member-rails.md)
的机制变更按仓库决策生命周期记录。

## 5. 异步任务内容与局部连接（F10/F11）

这是用户最新提出、待实页展示的细化方向，不将草案写成已认可视觉。

- 分离节点：以已记录的动作描述或命令/工具摘要为标题，旁边显示“转入后台”与发生时间。
  默认露出一至两行足以辨认工作的内容，而不是只写“Asynchronous tool”。
- 返回节点：沿用同一动作身份，显示返回状态与短结果摘录；错误优先于常规输出。
  “工具成功返回”与“内部命令退出成功”分别由实际拥有的记录决定。
- 时间：分离到收到结果与启动到收到结果是两种区间，必须分别命名。
  用户截图的时间可读为启动 11:30:28、分离 11:30:59、收到结果 11:31:05，
  即全程记录跨度 37 秒、分离后 6 秒；不能把两者都简称为“后台耗时”。
- 连接推荐为正文边缘的局部括线：在 detach 处从正文分出，在 return 处用箭头回到正文。
  中间不增加“主 Agent”一条轨道，细节中的完整时间图继续按需阅读。
- 连接默认低权重，选中任一端才强调成对端点；跨屏继续提供准确对端跳转。
  多次 wait 仍属于同一执行，不为每次轮询建一条关系；多次分离/返回按真实 occurrence 保留。
- 并行执行可使用少量局部槽位，不能复用成员颜色让人误认为一个新 Agent。
  未返回仅显示已知的分离端与最后记录；不补画返回箭头或持续运行的动画。

现有 `ReaderExecution` 保留 execution ID、类型、名称、steps；`ReaderExecutionStep` 保留
event、timestamp、归一化 observation 和正文位置。先复用这一绑定，在服务端从实际源内容
形成有长度边界的 action/result 摘录，不在浏览器猜命令结构。没有可读动作时使用具体工具名；
没有输出就如实显示对应缺失信息。源内容全文仍由原有日志/原文入口读取。

拥有文件：`src/reader-executions.ts`、`src/views/reader-executions.ts`、
`src/static/app/reader-executions.js` 及样式。视觉切片先与现有成员侧轨一起检查，再交付正式实现。

## 7. 续读连续性与格式（F12/F13）

同一字段/内容 owner 的分页是加载细节，不是新的消息或卡片。plain 内容追加到同一个原文区域，
保持空白；Markdown 内容在结构正确的前提下连续排版。每页仍有数据边界与可重试的加载入口，
不为视觉合并改成一次加载整段巨大历史。

当前格式规则（源码核对，不是另行更改产品选择）：

| 内容 | 格式 |
| --- | --- |
| 用户、Agent、助手正文与 reasoning | Markdown |
| 系统消息及继承的系统背景、工具输入 | 转义后的原文；结构化输入以 JSON/代码显示 |
| 字符串工具输出 | `auto`：按完整字段的 Markdown 特征判断 |
| 对象/数组工具输出 | 原始结构化数据 |
| 已识别问答 | 问题/答案专门排版，原始包装单独查看 |

分页使用相同格式决定，但不能将未闭合代码围栏、列表或表格当成互不相干的文档解析。
服务端复用现有 Markdown 块语法，以显式 continuation 元数据标记围栏、段落、表格和列表的
同块续页；浏览器只合并元数据指定的拥有块，不按 HTML 外形猜测，也不重传或重绘已经加载的前缀。
块分析只扫描端点，不构造整张表或整份列表的 HTML。

结构续页的单个不可分割单元上限为 65,536 个 JavaScript 字符串 code unit（UTF-16 code unit，
不是 UTF-8 字节）。普通请求页最多读取 6,000 个 code unit；为了在该页内保留一个完整且可合并的
行、列表项或内联原子，结构页最多前探到 65,536。若单个表格行、列表项、引用/标题、带跨页内联
语法的段落超过此界限，或巨大围栏的分隔行与 6,000-code-unit 内容页合计会超过此界限，
则该整个 Markdown 块改用连续的、已转义的源码区域分页，
只显示一次“大型 Markdown 块以源码显示”提示；块结束后恢复正常 Markdown。源码页仍最多 6,000
个 code unit，并避免在 UTF-16 代理对中间断开。HTML 转义和标签会扩大响应字节数，因此 65,536
描述的是源字符/扫描边界，不声明相同数值的 UTF-8 响应字节上限。

块分析按完整源字符串身份缓存，源变化不会复用旧计划；LRU 最多 4 项、总权重最多 4 Mi code unit
（源长度加范围索引估算）。超过预算的单个字段不进入缓存，会在各请求重新扫描块端点；响应仍有源字符上限，
浏览器仅追加当前页，不重复传输或重绘整个已加载前缀。保持 provider 文本只读与 HTML 转义，嵌入的提示词仅作为历史内容。
是否将系统原文改成 Markdown 是独立体验选择，本次先修复同一内容续读断开与格式连续性。

拥有文件：`src/views/components.ts`、`src/static/app/session-workbench.js`、Markdown helper
及内容分页相关测试；涉及服务端返回契约时同步 HTTP 消费者和搜索映射。

## 8. 常驻任务与协作面板（F14）

用户要求桌面右侧常驻，并在影响正文时贴边悬浮或收起。采用可停靠面板：

- 足够容纳目录、正文、成员侧轨和面板的桌面窗口默认停靠；面板顶端跟随阅读视口，内容独立滚动。
- 空间不足时使用贴边入口，打开后浮出；不缩窄正文来硬塞面板。布局变化由窗口尺寸或明确操作
  触发，不随正文滚动反复展开/收起。
- 手动收起/打开偏好保留；入口从开头到中段都可访问。无任务/协作内容时不占用空面板。
- 面板负责总览和查找，正文侧轨负责局部关系；选择同一 canonical 任务/成员，定位正文时
  保留面板状态，打开/关闭子历史与 Back/Forward 不突然重置整页。
- 本项验证桌面宽窗口和普通桌面窗口，不扩展窄屏产品范围。

拥有文件：现有 `session-reader.js` 面板控制、Reader 视图及 `reader.css` 面板区；
复用已有内容与状态，不再建立另一套任务目录或关系图。

## 9. 压缩目录节点（F15）

用户希望从左侧目录定位 compaction。目录新增独立的上下文节点类型，与正文使用同一个
checkpoint 身份和安放顺序，不在目录重新推断位置。节点使用可读“上下文压缩”及必要的
序号/时间区分多次压缩；样式与用户、助手和任务节点区分。

选择节点定位实际 checkpoint，并展开“压缩后保留的上下文”；未保存结果时读取原有准确说明。
该节点参加目录当前项高亮、键盘、刷新和 Back 路径；主/子 pane 各自拥有其 checkpoint，
继承背景中的压缩不重复进入 child 自身目录。正常发言数量与 usage 保持原口径。

拥有文件：正文/ToC 视图、相应导航控制器与 locale。此项改变原目录类型不变量，需要同步
AGENTS 与对应决策/测试，而不是把 checkpoint 伪装成 assistant 或 task。
