# Reader 实页反馈修订 spec

更新：2026-09-23。状态：实现与实页验收结果见执行账本。

产品依据：[呈现规范](../../design/runtime-presentation-contract.md)。
实施方案见 [design](design.md)，逐项进度与验收见 [tasks](tasks.md)。
本 spec 承接 R5 上线后的用户截图反馈；历史版本通过的验收不关闭本次新问题。

## 目标

让人连续回看完整会话：发言者清楚、过程集中、子历史原位展开、协作有联系，滚动不使卡片与轨道跳变。
正文就是主 Agent 的主线，侧轨只表示其他成员。默认简洁，逐层展开后仍能读完原始历史。

## 反馈与验收要求

| ID | 用户反馈 | 本次应满足的行为 | 可检查的验收 |
| --- | --- | --- | --- |
| F01 | 本地会话库只剩一个会话 | 正常查看入口指向实际完整本地库；隔离样本入口明确标为样本 | 从交付入口进入 `/sessions`，核对 provider、总数及过滤条件；不得把 3466 的单一 DSH 样本说成完整库 |
| F02 | 多条会话标题、项目相同，看起来重复 | 区分独立会话，提供足以识别的差异信息 | 同标题样本 canonical ID 与数量保持；独立打开、返回、搜索、管理仍对应各自会话；视觉方案按 Q3 确认 |
| F03 | 用户在右，Agent 在左 | 用户块靠正文右侧、Agent 保持左侧；文字仍正常左对齐 | 短句、长文、列表与代码实页可读；主历史与内联子历史一致；目录与侧轨位置不变 |
| F04 | 展开“View source record”后又是同名链接，重复且意义不明 | 单一、有明确目标名称的来源操作 | 一次操作直达该条调用或事件；没有同名折叠套同名链接；完整子历史入口独立且可用 |
| F05 | 展开子历史后出现断开的另一张卡片 | 子历史展开在触发卡片内部，视觉与交互连续 | 边界、底色与成员色连续；可收起并恢复触发位置和焦点；同一 child 不重复挂载，多级与 Back/Forward 保持 |
| F06 | 虚线是什么意思 | 明确表达记录范围，不把缺少后续记录画成持续运行 | 线尾按 Q2；不以 idle、单轮结束或结果返回推断成员终止；默认页面没有延伸贯穿无关内容的未知虚线 |
| F07 | 紫线消失、前后滚动列位置不同，有闪烁感 | 滚动只改变图的可见范围，不改变正文布局；仍显示的成员位置保持 | 对同一锚点前后滚动，卡片高度、正文宽度和文档坐标不变；保留成员的横向位置不变；选中/聚焦的节点不丢焦点 |
| F08 | 紧邻的“执行过程 1 条”和“执行过程 5 条”未合并 | 无可读正文或关键转折隔开时，默认呈现一个紧凑过程入口 | 示例显示一个共 6 条的入口；逐项展开顺序、原消息/工具锚点、reasoning 归属和用量不变；不吞并用户消息、结果、错误或上下文节点 |
| F09 | `teaching_devils_advocate` 卡片孤立，没有接上侧轨 | 已有关系不能因显示容量限制变成无说明的孤立旧版卡片 | 创建、追加与返回都可追踪；超额成员按 Q1 明确处理；滚动前后卡片样式与高度保持一致 |
| F10 | 异步任务默认只有类型、状态与时间，信息太少 | 分离处说明在做什么；返回处给出结果摘要与已知状态 | 可直接识别同一次执行、动作/命令摘录、返回内容；有时间证据才显示准确区间；不必先打开日志才能知道工作内容 |
| F11 | 异步任务的 detach 与 return 能否连起来 | 同一次执行在正文旁形成局部连接，不占永久成员轨道 | 从分离沿连接认出返回；跨屏可互相定位；并行、未返回、失败及多次等待仍可区分，原位展开后连接准确 |
| F12 | Show more 续读后内容被分成另一张卡片 | 同一字段继续填入同一内容面，不把传输分页当成阅读卡片 | 连续多页无重复边框/间隙；文字不丢不重；原有滚动、搜索、复制与长内容边界保持 |
| F13 | 卡片是否渲染 Markdown 由什么决定 | 明确内容类型的格式规则，首屏与续读一致；分页不破坏 Markdown 结构 | 正文/推理、系统原文、工具输入/输出分别核对；跨页代码围栏、列表与表格保持语义；不把代码片段误排成正文 |
| F14 | Tasks & collaboration 希望右侧常驻，遮挡时贴边或收起 | 桌面宽度足够时默认停靠，阅读中持续可达；空间不足或手动收起时保留贴边入口 | 从会话开头/中段均可使用；不依赖末尾按钮；浮出不挤压正文；记住手动选择；与正文、ToC、成员轨道和 child 导航联动 |
| F15 | compaction 也需要 index 记录 | 左侧目录按正文发生顺序加入独立上下文压缩节点，便于回看保留内容 | 节点与实际 checkpoint 一一对应；点击定位并展开保留内容；多次压缩、未保留结果、child 自身目录与 Back 均正确 |

## 已取得的依据

- F01：正常服务为 3456；3466 使用独立的原生 Teams 验收数据与元数据库。反馈来自入口混淆，
  不是用户 provider 数据被删除。最终交付仍需重新检查正常服务与过滤状态。
- F02：此前只读核对发现特定 CodeFacts 评测目录内 41 个不同 session ID 共用一个标题；
  36 个有评测计划记录，其他 5 个来源尚未逐条核对。不能因同标题合并或删除真实会话。
- F04/F05：用户截图中的 `rewrite_coordinates_lesson` 有独立 child；其最初任务正文在 Codex
  记录中加密。去掉重复 UI 入口不会恢复加密内容，缺失说明保留在真正受影响的内容处。
- F07/F09：当前控制器最多取四名成员，而且按当前入选人数重分配横向位置；只给入选成员的
  卡片应用紧凑样式，离选会移除样式。该逻辑同时影响连线可见性和正文高度。
- F09：2026-09-23 正常服务的 Codex 父会话 `01a0a037-4a13-79b3-882c-aeffacb1dd03`
  侧轨数据含 10 名成员；`teaching_devils_advocate` 的 child 为
  `01a0a59c-e7ad-79a1-b8d7-5fcf6733cd6e`，已有创建、追加、返回共 6 条关系。
  父引用和关系数据均存在；截图中的孤立呈现应从前端取舍与布局检查。
- F08：第一处为消息内部尾部过程，第二处为后续纯过程消息组；当前两种呈现分别折叠。
  修复的是相邻过程的阅读组织，不是把原始消息或模型请求合成新记录。
- F10/F11：现有异步插入只有类型、phase、时间与来源/对端链接；同一 execution 的步骤、
  身份与原始位置已经进入共享 Reader 投影。命令/输出摘录需要由该投影解析已绑定的原文，
  成败与时长只采用归一化执行字段和已保存时间，不根据截取文本猜测。
- F12/F13：通用 `renderProgressiveContent` 每页分别生成 `<pre>` 或 Markdown 容器；
  `loadProgressiveContent` 把响应再包成 `.progressive-chunk` 并追加。当前格式选择参考完整字段，
  但 Markdown 实际解析的是截取片段；需验证跨页围栏等结构。用户截图本身不能确认原消息 role。

## 保持的契约

1. Provider 数据只读，canonical 身份、关系、发送/收到时间及用量归属保持。
2. 完整正文、原始消息锚点、全文搜索、目录、子历史及返回路径保持可达。F15 明确扩展原来
   仅有请求/回复/任务的目录类型，新增有真实 checkpoint 的压缩节点，不把它算作一条发言。
3. 英中、明暗、桌面键盘与 reduced-motion 验收；保留现有响应式行为，不新增窄屏工作。
4. 使用现有 SSR、原生 JS/CSS 与语义投影。实测发现缺少共享事实时，才调整其拥有边界。

## 集中确认的体验问题

2026-09-23 已集中收到用户答复；下列选择用于实施。

| 编号 | 取舍 | 推荐方向 | 替代方向 | 状态 |
| --- | --- | --- | --- | --- |
| Q1 | 同时相关成员超过侧轨容量 | 保持窄侧轨与稳定槽位，优先眼前事件；超额关系给出紧凑的成员聚焦入口，点击切换关联，正文不变形 | 全体成员固定列，侧轨区域独立横向滚动 | 用户选择推荐方向 |
| Q2 | 最后一条记录之后如何收尾 | 轨道在最后一次交互收尾；新增交互读入后再延续，不画未知虚线，不额外重复提示未知 | 保留短虚线尾部与图例 | 用户提出“没有新的交互就代表结束”；按阅读轨道收尾落实，完成/退出文字仍依据记录 |
| Q3 | 同标题独立会话如何辨认 | 保留独立行，紧凑呈现精确时间及可用的差异摘录 | 相似标题形成纯展示折叠组，展开仍是独立会话，不宣称父子关系 | 用户选择推荐方向 |

F03–F05、F08 先推进，S2/S3 按确认结果实施；新增体验问题每批集中报告。
