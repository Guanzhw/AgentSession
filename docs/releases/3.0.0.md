# AgentSession 3.0.0

本版使用稳定版渠道发布。功能、升级方式和实际验证范围如下。

## 相比 v1.10.1 的变化

- **Rust 原生运行时。** Web Viewer 与独立 stdio MCP 共同使用 Rust core，
  Web 使用 Axum，前端使用 Svelte。独立程序运行时无需 Node.js 或 Cargo；
  npm 的 Viewer 和 MCP 入口共享原生程序。
- **完整会话阅读与来源导航。** 工具和推理归入产生它们的助手消息，压缩记录
  作为独立检查点呈现。子历史可在分派位置展开，Runtime 与正文可按来源往返。
  长正文按需续读，搜索结果可定位初始阅读窗口之外的匹配内容。
- **有界只读 MCP。** 会话检索、分层浏览、事件与上下文读取以及 DeepSeek
  Harness 团队消息检索保留 canonical 会话身份、来源修订和续页信息。
- **五个活跃 Provider。** 支持 OpenCode、Claude Code、Codex CLI、Pi 和
  DeepSeek Harness。OpenClaw、Hermes 的既有来源保留；元数据副本导入保留其历史行。
- **独立 Viewer 状态。** 收藏、标题和回收站状态保存在 Viewer 元数据中。
  Provider 数据库与 transcript 保持只读，永久删除操作在 Viewer 中永久排除会话。

## rc.4 之后的修复

- 正文搜索保留匹配位置、完整字段修订及高亮；子历史搜索、刷新和浏览器
  Back/Forward 恢复对应阅读位置与焦点。
- Runtime 跳转来源后返回，恢复筛选、页码、滚动位置和相关会话选择。
  会话库增加可组合的加星筛选，并显示各会话自身的收藏状态。
- 缺失会话提供明确的中英文说明和返回会话库入口；回收站区分完整、部分和
  失败读取，来源诊断链接到相应配置位置。
- 补齐 DeepSeek Harness generation-4、workflow 记录及当前 Claude Agent
  分派形状的解析。真实压缩、分支、团队与队列记录保留来源证据；缺失或冲突的
  历史仍明确显示为不可用或未知。
- npm Viewer 入口正确转发 `serve`、`mcp`、`migrate-meta` 和 `help`；不带子命令
  时默认启动 Viewer。独立 MCP 入口继续运行 stdio 服务。

## 安装与升级

稳定版使用 npm `latest` 渠道；预发布版继续使用 `next`。

```sh
npm install -g @acetamido/agentsession@3.0.0
npm install -g @acetamido/agentsession-mcp@3.0.0
agentsession
```

npm 入口需要 Node.js 22.15 或更新版本。发布流程提供 Windows x64、Linux x64、
Linux arm64、macOS arm64 独立程序包，以及 `SHA256SUMS` 和 npm 来源清单。
默认 Viewer 地址为 `http://127.0.0.1:3457/sessions`。

从旧版升级时，先保留旧配置和包含已提交 WAL 数据的一致 SQLite 备份副本。
为 3.0 配置绝对来源路径及独立 `metaDir`、`indexDir`、`cacheDir`，在首次编辑
新版收藏、标题或回收站前导入旧 Viewer 元数据：

```sh
agentsession migrate-meta --from /absolute/old-meta-copy.db --config /absolute/config.json
agentsession --config /absolute/config.json
agentsession-mcp --config /absolute/config.json
```

Viewer 与 MCP 是独立进程；按需分别启动。独立包使用 `agentsession-v3 migrate-meta`、
`agentsession-v3 serve` 和 `agentsession-v3 mcp`，Windows 文件名带 `.exe`。
已有目标元数据时导入会拒绝覆盖；保留当前状态，改用另一个 `metaDir` 导入检查。
导入保留完整旧数据库，但不合并旧版与新版编辑。具体步骤见
[元数据迁移指南](../../v3/README.md#viewer-metadata-import)。

MCP 注册应指向新入口与选定配置。Reader 和 Runtime API 客户端使用 `/api/v3`；
Protocol 2/3 继续表示原生事实文档的 schema 版本。

## 验证记录

发布流程逐平台验证原生包、Web/MCP 和安装行为，再组合四平台 npm tarball 并
离线安装验证。当前候选五个 Provider 的真实来源、桌面阅读与返回流程、人类任务
反馈、Windows/Linux 安装及四宿主 CI 已取得通过证据。

本次按用户明确指令发布，尚未完成全部性能和资源验收：配对读取、来源变化、
Windows Reader 测量、完整共享资源重复仍开放。已有搜索和资源运行的内容检查
通过，但默认旧索引在测量期间变化，整轮状态保全检查失败；历史 STATE-01 的
具体写入进程仍未归因。发布不将这些结果改记为通过，也不据此宣称完整性能提升。
确切候选、执行结果与[发布裁决](../../.agents/decisions/implemented/2026-10-12-user-authorized-stable-publication.md)
见[稳定版任务账本](../specs/stable-readiness-2026-10/tasks.md)。
