# AgentSession 3.0.1

本版是稳定版发布候选，目标为 npm `latest` 和普通 GitHub Release。
提交与发布已获授权；最终整合提交的 CI、四平台产物和公开安装验证尚待完成。

## 安装与升级

发布后可锁定版本安装：

```sh
npm install -g @acetamido/agentsession@3.0.1
npm install -g @acetamido/agentsession-mcp@3.0.1
agentsession
```

npm 入口需要 Node.js 22.15 或更新版本。预发布渠道继续使用 `next`。
从 v1.10.1 升级的端口、MCP/API 和元数据导入步骤见
[3.0.0 更新说明](3.0.0.md)与[元数据导入指南](../../v3/README.md#viewer-metadata-import)。

升级会自动刷新旧派生摘要和 Reader 缓存：摘要 schema 为 16，Reader cache
schema 为 3，projection 为 11。首次读取可能重新捕获来源；Provider 数据和
Viewer 收藏、标题、回收站状态保留。旧程序会明确拒绝较新的缓存 schema，
回退运行应使用其兼容的独立派生状态目录。

## 修复与行为

- **Codex 发现与 Token 统计。** 新状态下按 canonical 会话身份发现记录，兼容
  旧 `session_id` 头。普通 `token_count` 的累计增量计入已知 Token 小计，重复
  快照不重复计数；请求数继续要求明确请求身份。趋势、Harness 与模型份额默认
  按 Token 展示。保留 main 的实时 catalog 捕获与来源一致性修复。
- **Claude 用量。** 按 response 选择并去重 pending 用量，保留已记录的 Token
  分量。完全缺失 `usage` 时摘要保持未知，Protocol 不伪造请求；混合记录保留
  已知合计，缺失记录不抢占同一 response ID，原消息保持可读。
- **DSH 歧义诊断。** 已知歧义会话保留为诊断行，数量保持未知，搜索报告部分
  覆盖，统计明确计入排除来源。直接读取继续报告来源错误。
- **Reader 错误。** 冷读、缓存与重启后均保留具体 Protocol 错误及可读正文。
  HTTP 422 `protocol_invalid` 返回最多 20 条诊断与截断标记；界面显示原因、
  诊断码和来源事件。保留 main 的缺失子历史提示。
- **MCP 与内部一致性。** 原生 MCP 的安全诊断写入 stderr，wire 响应保持。
  移除无调用方的非索引列表分支；批量元数据操作共享逐来源预检与写入路径，
  保留事务与部分提交语义。保留 main 的 OpenCode WAL 和测试夹具清理修复。
- **Linux 浏览器门槛。** Linux x64 native/release CI 必跑公开浏览器回归，
  锁定 agent-browser 0.39.1，检查 Chrome 并先执行启动 smoke；缺工具、UI
  依赖或浏览器时明确失败。独立浏览器工具需要 Node.js 24+，项目开发最低版本
  仍为 Node.js 22.15。
