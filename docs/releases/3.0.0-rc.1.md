# AgentSession 3.0.0-rc.1

本次为 3.0 的预发布候选，更新说明以最近公开发布的
[v1.10.1](https://github.com/Guanzhw/AgentSession/releases/tag/v1.10.1) 为基准。
npm 使用 `next` 渠道。

## 相比 v1.10.1 的变化

- **默认运行时改为 Rust 原生实现。** Web Viewer 和独立 stdio MCP 共同使用
  Rust core，Web 使用 Axum，前端改为 Svelte。源码开发需要 Rust；独立程序运行
  时无需 Node.js 或 Cargo。npm 安装提供两个轻量入口，共享同一份原生程序。
- **阅读器由 Svelte 重新实现并细化呈现。** 连续阅读、就地子历史、彩色协作
  连线、相邻执行过程收起和目录折叠延续 1.10.1；工具与推理按产生它们的助手消息归组。
  工具卡片显示可用的动作、Agent 名称、模型和推理强度，完整输入输出按需展开；
  上下文压缩以独立检查点卡片呈现。
- **原生 MCP 提供七个只读工具。** 相比 1.10.1 的五个工具，增加分层浏览
  `session_browse` 与 DeepSeek Harness 团队消息检索 `session_team_messages`。
  返回保留 canonical 会话身份、来源修订和续页信息，并提供有界摘要。
- **来源索引与正文缓存改为原生实现。** 复用经过完整来源修订验证的 Codex
  捕获结果，减少重复读取；已有字段的输入/输出续读绑定内容快照，后续追加事件
  不再使该字段的匹配快照失效。
- **支持范围收敛为五个 Provider。** 当前读取 OpenCode、Claude Code、Codex
  CLI、Pi 和 DeepSeek Harness。OpenClaw、Hermes Agent 的历史来源文件保留，
  其 Viewer 元数据在数据库副本导入时保留。

## 性能实测范围

以下数据来自同一份约 918 MB 的冻结 Codex 会话、同语义输出的优化前后对比：
首次建索引耗时降低约 **15–20%**，暖读取约 **0.6 秒**。受控追加更新的收益有
波动，超长会话仍需重新解析来源。数据覆盖完整 HTTP 返回和 JSON 解析，浏览器
绘制时间另计。测量方法和完整内容一致性检查见
[性能报告](https://github.com/Guanzhw/AgentSession/blob/v3.0.0-rc.1/docs/design/performance-incremental-20261011.md)。

## 安装与升级

```sh
npm install -g @acetamido/agentsession@3.0.0-rc.1
npm install -g @acetamido/agentsession-mcp@3.0.0-rc.1
agentsession
```

npm 入口需要 Node.js 22.15 或更新版本。也可下载本 Release 的 Windows x64、
Linux x64、Linux arm64、macOS arm64 独立程序包；每个包包含程序、许可证、
公开样本、MCP 注册脚本和校验清单。独立包内的示例命令使用公开样本；阅读个人
历史时请按配置文档设置实际来源路径。

- **默认端口改为 `3457`**，Viewer 地址为 `http://127.0.0.1:3457/sessions`。
- **保留旧配置和元数据备份。** 使用独立程序的
  `agentsession-v3 migrate-meta --from <旧 Viewer 数据库副本> --config <3.0 配置>`
  显式导入到选定来源范围。已验证与 v1.10.1 表结构匹配的真实数据库副本导入，
  全部表内容保持一致；已有 3.0 状态不会被覆盖。配置和派生索引需按 3.0 重新设置。
- **MCP 注册需要核对新入口和来源路径。** npm 使用 `agentsession-mcp`；独立包
  使用原生程序的 `mcp` 子命令。显式指定配置、来源与状态目录。
- **HTTP 会话接口迁移到 `/api/v3`。** 已识别的旧接口返回 `410` 和迁移信息；
  API 客户端应使用新路由、事件引用和续页游标。Protocol 2/3 继续表示原生事实
  文档的 schema 版本。

具体命令见
[原生配置与迁移文档](https://github.com/Guanzhw/AgentSession/blob/v3.0.0-rc.1/v3/README.md)。

## 验证与已知限制

发布流程对四个平台分别构建并检查安装包的 Web、MCP、安装器和独立运行行为，
再于 Linux 组合并离线安装实际多平台 npm tarball。Release 提供 `SHA256SUMS`
和原生包来源清单。

Windows 真实数据检查覆盖旧元数据副本导入、全部表内容保全、退役 Provider
元数据保留、只读 Web/MCP 访问及重启；Provider 原始文件保持不变。
仍存在尚未覆盖的最新或稀有来源格式；缺失或冲突的历史会明确报告。此次预发布
不关闭验收契约中尚未补证的全部来源、资源与产品门槛。
