# 前端实现 · P2:对话线程化(最难的阶段)

```text
P2 目标:对话页从线性改为线程,长会话可读。这是三个痛点修复的核心(§2 痛点2)。
注意:对话标签非默认(工作为默认标签,已实现决策 2026-09-02);本阶段只做
对话投影本身的信息设计。

范围(§4.3 + §4.7 场景 1/2):
1. 线程结构:以用户轮次为根分段;段内按因果挂助手回复→工具调用→子代理分支;
   嵌套 ≤3 层(轮次>回复>工具/子代理),推理附着在所属助手/工具下;
2. agent 卡(取代一次性子代理卡):跨轮活跃区间、消息数、最后活动、状态
   (活跃/等待/被打断/完成);展开 = agent 频道(coordination 观察的时间线:
   消息/信箱投递/打断/交接/结果交付+确认),默认折叠;
3. 主对话流规则:只保留"用户↔主 agent"主线与派发/交付锚点;主 agent 对既有
   agent 的再次通信显示一行轻量引用;agent 间往来全部进频道;
4. 压缩检查点内联合并呈现:before→after tokens + 压缩后上下文摘要,展开看详情
   (数据来自 context 投影 transformation + 事件;不重复两处);
5. 工具卡:标题行+状态;小调用折叠一行;输入/输出默认折叠、渐进加载(沿用现有
   progressive API);子代理/agent 卡点击可跳子会话,返回路径保留;
6. 右侧检查器:会话信息/过程记录完整度(一行)/消耗(输入/输出/总计;当前后端尚未
   暴露 origin 聚合——work-graph spec Evolution backlog 第 1 项,核心后端工作之一——
   未落地时如实只显总量,不得显示三分)/会话关系
   (带类型:分叉自/接续/派生出,超 5 条给谱系图入口)/记忆与经验资产区(按 scope
   分组,条目带来源任务链接)/操作;
7. 大纲按线程结构;TOC 可调宽(继承现有);会话内搜索保留;
8. 线程(默认)/原文线性 切换;短会话(≤20 条消息)默认直接用线性(§11 开放问题2,
   未决:仅涉及对话标签页内默认)。

验收(§4.7 场景 1/2 逐条人工走查):Codex 真实会话里能看到 compact 检查点位置与
摘要;能看到 subagent 创建位置、首次返回时间、再次通信的轻量引用、频道完整序列;
长会话(13 任务/13 子代理/10× 压缩,研究时点 2026-09-02)扫读可理解。长会话/工具密集/窄屏/锚点跳转全通过。
建议拆两个提交:线程结构先行,检查器与频道随后。
```
